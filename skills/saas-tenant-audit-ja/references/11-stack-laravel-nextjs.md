## テナンシーモデルの確認（どのスタックでも）

- テナントは**認証済みの ID**（トークン → ユーザー → テナント）から得るもので、リクエストの
  フィールドから得てはいけません。クライアントが渡すテナント ID は、せいぜい ID と照合されるべき
  *セレクター*にすぎません。[std]
- テナントは、すべての取得処理、**キャッシュキー**、レート制限のキー、キューのペイロード、
  ファイルパスに含めます。キューのコンシューマーやスケジュールジョブの内部でテナントの
  コンテキストを再確立します。[std]
- 一意性（スラッグ、サブドメイン、独自ドメイン、名前）は、アプリケーション側の事前チェックではなく、
  データベースのユニークインデックスで、意図したスコープごとに強制します。[std]
- 公開識別子（スラッグ、サブドメイン）には再利用ポリシーを定めます（`03`）。[field]

## Laravel

- **インベントリ**: `php artisan route:list --json`。middleware 列を読みます。[std]
- **テナントスコープ付きの取得関数**: ハンドラーごとの `where('tenant_id', …)` よりも、
  全ハンドラーが使う 1 つのヘルパー（`findForTenantOrFail($id, $tenantId)`）のほうが優れています。
  404 の規約も同時に強制できます。[field] 適する場面ではグローバルスコープやポリシーを優先しますが、
  ブラックボックスでの結果を必ず検証してください。スコープは `withoutGlobalScopes`、生クエリ、
  join、`DB::table` では回避されます。
- **ルートモデルバインディング**はスコープなしだと、ID で任意のテナントの行を取得します。
  スコープを付ける（`scopeBindings`、独自の `resolveRouteBinding`）か、バインドしないでください。[std]
- **データベースにアクセスするバリデーションルール**（`exists:`、`unique:`）は、既定では
  テナントスコープ付きではありません。`exists:items,id` は行がどこかに存在することを示すだけで、
  呼び出し元のものであることは示しません。[std] これは存在オラクルでもあります（422 と 404 の差）。
- **マスアサインメント** [field/std]: `$fillable`/`$guarded` を両方向で確認します。
  (a) 特権のあるカラム（テナント、ロール、ステータス、クォータのカウンター）はリクエスト入力から
  fillable であってはならない。(b) *コード*が書き込むカラムは fillable でなければならず、
  さもないと書き込みが黙って捨てられる（書き込まれないカラムを「数える」クォータは無制限になる）。
  `$request->all()` より `$request->validated()` を優先します。
- **論理削除とステータス** [field]: `is_deleted` 型のフラグは `SoftDeletes` ではありません。
  すべての取得処理（公開、ジョブ）が不変条件を適用しているか確認します。再利用可能なスコープ
  （`scopeLive`）が役立ちます。
- **キュー/ジョブ** [field]: ジョブは実行時に状態を再読み込みする。`retry_after` は最長のジョブの
  `timeout` より大きくする。リソースごとのジョブには重複防止の middleware を使う。ワーカーが複数ある場合は
  二重実行がないことを確認する。
- **レート制限** [field]: 明示的なキーを持つ名前付きリミッター（識別子+IP、公開書き込みは
  IP のみ、認証済みはユーザー）。カスタムのスロットル応答は、クライアントが読む JSON と
  同じ形を返すようにします。リミッターの状態をデータベースのキャッシュに置くと、キャッシュを
  クリアするデプロイでカウンターも消えます（同じストアを共有していればセッションも消えます）。
- **実際のクライアント IP** [field]: ピアがループバック/プライベートのときだけ動作し、プロキシが
  書き込んだヘッダーを信頼し、CDN のヘッダーは CDN の範囲からの場合だけ信頼するグローバル
  middleware。`trustProxies('*')` は避けます。CDN の範囲リストは定期的に更新します。
- **パスワード** [field]: 最小長と漏えい済みでないことのチェックを備えた `Password::defaults()`。
  漏えいパスワード照会のクライアントのタイムアウトを調整し、登録・変更・リセットにのみ適用します。
- **設定キャッシュ** [std]: `.env` を変更したら `config:clear` の後に `config:cache`。
  設定がキャッシュされていると、設定ファイルの外での `env()` は null を返します。
- **デバッグ** [field]: `APP_DEBUG=false`。不正なリクエスト 1 件でエラーページを確認します。
- **ログ** [field]: 保持期間を設けた `daily` チャンネル。本番ではデバッグレベルでも
  リクエストボディやトークンを記録しない。
- **正規表現** [field]: PHP で文字列全体を固定するには `$` ではなく `\z` を使います。
- **HTTP クライアント**: 外向きの呼び出しはガード付きの取得処理（`05`）だけを通します。
  ユーザーが影響できる URL に対する生の `Http::`/`curl` は、コードレビューで禁止します。
- **メール**: 宛先をユーザーが制御できないようにする。メールはキューに載せる。テストでは
  予約済みドメインの偽アドレスを使う。

## Sanctum / API トークン [field]

- トークンごとの `expires_at`（新規トークンのみ）と、グローバルな `expiration`（遡及して適用）の違い — FL-19。
- ログイン時にすべてのトークンが取り消されるか（単一セッション）。取り消しテストを設計する前に把握しておきます。
- パスワード変更とリセット: 他のトークンを取り消す。メールアドレス変更: 現在のパスワードを要求する。
- Bearer トークンには `|` が含まれます。シェルのフィクスチャで `source` してはいけません。（FL-07）
- 期限切れトークンは定期的に削除する（`sanctum:prune-expired`）。
- 管理者ゲート: 全テナント対象のルートには専用の middleware、管理者トークンには abilities。

## Next.js

- **ルートハンドラー（`route.ts`）は、保護しない限り公開 HTTP エンドポイントです。**
  [field: 認証なしのキャッシュ再検証ハンドラー] 共有シークレットを要求し（未設定なら 503、
  不一致なら 403）、入力を厳密に検証し、サーバー間からのみ呼び出し、プロキシでインターネットから
  遮断します（`07`）。
- **Server Actions は公開の POST エンドポイントです**: 各アクションの*内部*で認証と認可を行い、
  引数は悪意あるものとして扱い、ページが隠れていることに頼らないでください。[std]
- **middleware/プロキシは唯一の認可レイヤーではありません。** フレームワークにパッチを当て続け
  （広く公表された middleware バイパスの CVE では、細工した内部ヘッダーで middleware をスキップできた）、
  データ層でもアクセスを再確認します。[std]
- **ビルド時の公開変数**（`NEXT_PUBLIC_*`）はバンドルに埋め込まれます。CAPTCHA のサイトキーには
  問題ありませんが、シークレットには絶対に使わないでください。変更には再ビルドが必要です。[field]
- **API へのリライト/プロキシ**: プロキシがどのヘッダー（実 IP）を設定するかを把握し、
  API がクライアントの渡す同名ヘッダーを信頼してはならないことを確認します。[field]
- **ISR / キャッシュ**: 公開、非公開、削除、スラッグ変更、ドメイン変更の後、キャッシュが*すべての*
  利用側（ページ、サイトマップ、フィード、機械可読な要約）で無効化されるか。それぞれテストします。
  [field] 利用側（動的とプリレンダリング）ごとに、失敗は独立して起きます。
- **ホストベースのルーティング（独自ドメイン）**: アプリは `Host` → テナントの対応付けを行います。
  未知のホスト、削除済みテナントのホスト、未登録のホストがページを埋め込もうとする場合
  （frame-ancestors）が、フェイルクローズ（安全側に倒す）になることを確認します。テナントを
  クライアントのヘッダーから取得してはいけません。[field]
- **XSS**: `dangerouslySetInnerHTML`、リッチテキストのフィールド、URL フィールド
  （`javascript:` スキーム）、Markdown レンダラー、サードパーティの埋め込み HTML。
  URL スキームは許可リスト方式にします。[std/field]
- **画像**: アップロード前のクライアント側リサイズはサイズを減らしますが、検証ではありません。
  種別/サイズ/寸法はサーバーで強制し、プライバシーが重要なら EXIF メタデータを除去します。
  [field/std]
- **エラー/リダイレクトの処理**: 401 → ログインへのリダイレクトは、テストすべき UI 上の経路です。
- **CORS・CSRF・トークンの保管** [std]: 緩いCORSポリシーとCookie認証の組み合わせはクロスサイトのリスクになります。`localStorage` のトークンは、XSSがあれば読み取られます。APIのCORS許可リスト、Cookieの属性（`Secure`、`HttpOnly`、`SameSite`）、状態を変更するルートにCSRF対策が必要かを確認します。
- **テナントごと・認証済みページのCDNキャッシュ** [std]: `Cache-Control` と `Vary` を確認し、あるテナントの応答が別のテナントに配信されないようにします。ソースマップやデバッグ用ルートが公開されていないことも確認します。

## Laravel と Next.js の継ぎ目 [field]

- 両者は別々にデプロイされます。両方を必要とする変更（新しいシークレットヘッダー、新しい必須
  フィールド）は、空白期間が生じない順序で行う必要があります（`10`、FL-21）。
- 内部呼び出し（Next → API、API → Next）は内部アドレスを使い、それらへの外部からの
  ルートは遮断します。
- 共有シークレットは両方の環境ファイルに置きます（モード 600）。両方を一緒にローテーションし、
  依存関係が要求する順序で再起動します。

## マルチテナント SaaS 固有の事項

- 課金状態はテナントごとです。Webhook ハンドラーは検証済みの外部 ID からテナントを解決し、
  解決できなければ何もしない必要があります（FL-28）。
- プランの上限: サーバー側で強制する。個数の上限（プランごとのアイテム数）と月間クォータの
  両方が対象です。並列に作成すると、個数の上限を並列度の分だけ超えられます（`08`）。
- 公開されたテナントのページ、ウィジェット、フォームは匿名の攻撃面です: `04` を適用します。
- 管理者/サポート用ツール: 別のゲート、監査証跡、リクエストのフィールドによるテナント切り替えの禁止。
- データのエクスポート/削除の要求: 保持期間と、公開面から何が消えるかを定義します。

## クイックプローブ（ブラックボックス、安全）

```
# unauthenticated access to every protected route → expect 401
# tenant A token on tenant B ids → expect the agreed denial (404)
# A token on never-existed id → identical to the line above
# public write endpoint with a non-existent target, a dozen times in a row → 429 on the limiter's count
# public endpoint for a deleted/unpublished resource → identical to never-existed
# webhook endpoint with no/forged signature → 4xx; with signature from an empty secret → 4xx
# malformed request to trigger an error page → generic response, no stack trace
# origin address directly on 80/443 and app ports → refused/timeout
```

## 他のスタックへの移植

手順自体はスタックに依存しません。変わるのは調べるコマンドだけです。出発点（最新のドキュメントで確認してください）:

| 必要なもの | Laravel | Django / DRF | Rails | Express / Nest | Spring |
|---|---|---|---|---|---|
| ルートのインベントリ | `route:list --json` | `show_urls` / ルーターの登録、ビューセット | `rails routes` | ルーターツリー / デコレータ | Actuatorのマッピング、またはコード検索 |
| テナントスコープ付きの取得 | ヘルパー1つ + スコープ | テナントで絞る `get_queryset()` | `default_scope` / `acts_as_tenant` | テナント引数付きのリポジトリメソッド | `@PreAuthorize` + テナント対応のリポジトリ |
| マスアサインメント | `$fillable` / `validated()` | シリアライザの `fields` / `read_only_fields` | strong parameters | DTOのホワイトリスト | DTOバインディング |
| トークンの有効期限 | トークンごとの `expires_at` | トークンモデルは既定で期限なし: 追加する | Devise/JWTの設定 | JWTの `exp` + 失効リスト | JWT/セッションの設定 |
| バックグラウンドジョブ | キューの `retry_after` | Celeryのvisibility timeout | Sidekiqのリトライ | BullMQのロック時間 | スケジューラ/ロックの設定 |

行レベルのテナント分離では、すべてのクエリ経路を確認します。テナントごとのスキーマでは、スキーマの選択方法と、リクエスト/ジョブごとのリセットを確認します。自分のスタック用のメモファイルを同じ形式（出典タグ **[field]**/**[std]**）で追加し、英語版と日本語版を同期させてください。

# 01 — 偵察とエントリポイントのインベントリ

目的: サーバーに何かをさせる方法を「すべて」網羅した表を作り、それぞれを判断するために必要な列を揃えることです。実際の監査における重大な指摘事項のほとんどは、誰かの頭の中のリストから漏れていたエントリポイントでした。リストは記憶からではなく、機械的に作成してください。

## A. リストの入手先

**外部の顧客として（ブラックボックス）**

1. ブラウザを使って顧客と同じように製品を使い、ネットワーク呼び出しを記録します（HARエクスポートまたはdevtools）。メソッド、パス、ボディの形、レスポンスの形を控えます。
2. フロントエンドのJavaScriptバンドルを読みます。APIのベースパス、fetch/axiosのラッパー、ルートのように見える文字列リテラルを検索してください。APIモジュールが一箇所にまとまっていれば幸運で、そうでなければチャンクをgrepします。フレームワークのビルド成果物は、仕様上、公開されています。
3. 公開面: `robots.txt`、`sitemap.xml`、機械可読なサマリー、公開JSONフィード、テナントごとの公開ページ、埋め込みウィジェット、Webhookの受信口（シークレットが見えなくても、存在は見えます）。
4. エラーとステータスの挙動: 推測したパスに対する401・404・405の違いから、ルートが存在するかどうかが分かります（`02` の存在オラクルを参照）。積極的なファジングはしません。
5. ホスト名ごとのレスポンスヘッダー（CDN、フレームワーク、サーバー）、apex・サブドメイン・テナントのカスタムドメインにおけるTLS／リダイレクトの挙動。

**コード・設定にアクセスできる場合（第二のレンズ）**

- Laravel: `php artisan route:list --json`（メソッド、URI、ミドルウェア）。認証ミドルウェアがないルート、テナント／権限チェックがないルート、公開POSTを控えます。
- Next.js: `app/**/route.ts` のハンドラー、Server Actions（それぞれが公開POSTエンドポイントです）、`middleware`/`proxy` のマッチャーとリライト、`next.config` のヘッダー／リライト。
- リバースプロキシの設定: どのパスがどこへ転送されるか、どのヘッダーが設定されるか（実IP）、何が転送「されない」か、CDNなしでオリジンに到達できるか。
- スケジュールジョブ、キュージョブ、Webhook: ユーザーセッションなしで動作するため、見落とされがちです。（FL-04）
- 外向き呼び出しのすべての箇所（HTTPクライアント、`curl`、URLのファイル読み込み）。（FL-15）
- 有料API呼び出しのすべての箇所（LLM、画像、STT、SMS、メール）。（FL-11, FL-16）

## B. インベントリの表

(メソッド, パス) ごとに1行です。列は次のとおりです。

| 列 | 意味 |
|---|---|
| Auth | none / user token / admin / signature (webhook) / secret header |
| Tenant scope | テナントをどう導出するか: トークンから（良い）、またはリクエストのフィールドから（検証が必要） |
| IDs accepted | パスパラメータ、クエリパラメータ、**さらにJSONボディ内や保存済みJSONフィールド内のID** |
| State rule | どのリソース状態を許可するか（draft/published/deleted/expired） |
| Side effects | 書き込み、メール、決済、AI呼び出し、ファイル保存、キャッシュのパージ、キュージョブ |
| Cost | none / cheap / paid per call |
| Rate/quota | リミッターのキー（IP? ユーザー? テナント?）、月次の上限、サイズの上限 |
| Denial convention | 他人のリソースや存在しないリソースに何を返すか（例: どちらも404） |

テンプレート: `templates/authz-matrix.md`。

## C. 各行を分類する

- **公開の書き込み**（匿名POST）: 悪用のリスクが最も高い → フェーズ4。
- **IDを受け取る認証済みエンドポイント**（任意の `{id}`）: テナントをまたいだ露出 → フェーズ2。
- **状態を持つリソース**（削除／公開／期限のフラグがある）: → フェーズ3。
- **URLを受け取るもの**（サーバーがユーザー指定のURLを取得または保存する）: → フェーズ5。
- **トークン／資格情報／リセット／Webhook**: → フェーズ6。
- **管理者専用**（全テナントのデータ）: ルート「および」非管理者に返されるデータの両方で、管理者ゲートを確認します。→ フェーズ2。

## D. 到達可能性と重要度（FL-29）

UIから呼び出されていないルートは、コードに関する事実であって、製品に関する事実ではありません。記録はしますが、*修正*の優先順位付けでは、到達可能性と実際の利用状況（行数、ログ）で順位を付けます。監査からは外さないでください。バックエンドは完成していてUIがない機能も攻撃対象領域であり、UIがないことは、多くの場合、誰もそれをテストしていないことを意味します。

## E. 出力

インベントリが大きい場合は、続行する前にユーザーへ渡します。予期しない行（忘れられた管理者ルート、デバッグ用ルート、古いAPIバージョン）は、それ自体が指摘事項です。

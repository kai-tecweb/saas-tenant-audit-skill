# 00 — スコープ、認可、安全な運用

## 認可チェックリスト（プローブを1つ送る前に答えること）

- [ ] 自分が対象を所有している、または所有者がこのテストを許可している（できれば書面で）。
- [ ] 環境が明示されている: ローカル / ステージング / 本番。本番の場合は、所有者が明示的にそう述べている。
- [ ] 自分のアカウントとテナント（「検証用テナント」）を作成でき、終了後に削除してよい。
- [ ] スコープ外が書き出されている（サードパーティのプロバイダ、他のテナントの実データ、サービス妨害型の負荷、ソーシャルエンジニアリング、物理的アクセス）。
- [ ] 想定外のこと（実在する顧客へのメール送信、データの変更、サービスの遅延）が起きたときに連絡できる担当者がいる。

一つでも未チェックの項目があれば、質問してください。対象に到達できるという事実から、認可を推測してはいけません。

## アクセスレベル

一部の手順（データベースのスナップショット、キャッシュやレート制限カウンタの消去、サーバーログの読み取り）は、通常の顧客アカウントを超える、検証用環境へのアクセスが必要です。自分がどのレベルかを明記してください。**顧客レベル**（APIとWebのみ）か、**環境レベル**かです。顧客レベルでは、スナップショットをAPI経由で取り（被害側テナント自身の一覧・詳細エンドポイントを*被害側として*読む）、クリーンアップは製品自身の削除エンドポイントと新しい識別子で行い、検証できなかったことを一覧にします。

## 本番環境でのテストのルール

実際のプロキシ経路、CDN、キューワーカー、データ量があるのは本番だけ、ということはよくあります。そのため本番でのテストが必要になる場合があります。次のようにして安全にします。

1. **検証用テナントだけを使う。** 偽の、明確にそれと分かるデータと、一意の実行プレフィックス（例: `audit-<epoch>`）を付けて、新しいテナントを2つ（A = 攻撃側、B = 被害側）作成します。実在する顧客を被害側に使ってはいけません。
2. **すべてのメールに、予約済みドメイン上の偽のアドレス**（`example.invalid`、`example.test`）を使い、実在する受信箱に何も届かないようにします。メールの実配信を証明する必要がある場合は、自分が所有するメールボックスを一つだけ使います。
3. **制限のテストには、副作用のない対象を使う。** レートリミッターがカウントした「後」で、かつ副作用の「前」に失敗するルートを通してリミッターを作動させます（存在しないIDなら、メール・AI・決済の呼び出しなしで404になります）。（FL-16）
4. **負荷テストはしない。** 並行処理のテストは、数千ではなく数十のリクエストとし、自分の検証用テナントに対してのみ行います。（FL-17）
5. **前にスナップショットを取り、後で差分を取る。** 触れるテーブルごとの行数に加え、キャッシュ・キュー・ログの成果物も対象にします。クリーンアップは「前 == 後」の確認で終えます。（FL-05）
6. **コストを意識する。** 有料APIを呼び出すもの（LLM、画像生成、音声認識、SMS）は、明示的な了承が必要です。ベンダーへの呼び出しの前に拒否されるパスを優先してください。
7. **重大度が不確かな場合、無害な確認リクエストは1回だけ。** 分類に必要な範囲を超えて悪用しません（`10-reporting-and-severity.md` を参照）。

## 絶対にしてはいけないこと

- 目にしたシークレットを、出力・保存・送信しない。その*存在*と場所の種別（ファイル名、キー名、件数）だけを記録して、そこで止めます。（FL-23, FL-33）
- 他の顧客の実データや、サードパーティのシステムを、「ちょっと見るだけ」であってもテストしない。
- 本番を劣化させかねない攻撃的な手法を使わない（大量の列挙、巨大なペイロード、slow-loris、実在するアカウントへのブルートフォース）。
- テスト用のユーザー、トークン、ファイル、キャッシュキー、キューの行を残さない。
- レビュー済みの1ステップのスクリプト、先に明示したロールバック手順、権限なしで事後に検証する方法がないまま、特権（root/sudo）を使った変更を実行しない。（FL-32）

## 環境の忠実度に関するメモ

- ローカルの実行環境には、本番にある拡張機能やサービス（HTTPクライアント拡張、画像ライブラリ、実際のプロキシ）が欠けていることがよくあります。ローカルでテストできなかったことを明記し、実際のホスト上で検証用のスクリプトを使ってテストしてください。（FL-31）
- 自分のツール自体がCDNにブロックされることがあります（デフォルトのHTTPクライアントのUser-Agentだと403）。プローブにはブラウザ相当のUAを使い、その旨を記録します。（FL-12）

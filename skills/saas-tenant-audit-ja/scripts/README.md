# scripts/

すべてのスクリプトは外部依存なし（Python 3標準ライブラリとBash）で、秘密情報の値を出力しません。

| スクリプト | 目的 |
|---|---|
| `tenant_probe.py` | 2テナントのブラックボックスのリクエストをJSONの計画から実行します。1リクエスト1行で `expected=` と `actual=` を併記します（許容するコードのリストも可）。正の対照、「存在しないIDと同一か」（存在オラクル: ステータス、本文の構造、JSON以外はハッシュ）、被害側データのスナップショットが変わっていないこと（直前のスナップショットと比較）を検査します。リダイレクトは追従しません。`--preview N` を付けない限り本文は表示しません。失敗があれば終了コード1です。 |
| `selftest.sh` | `tenant_probe.py` が「失敗できる」ことを証明します。安全なモックサーバーには合格し、わざと脆弱にしたもの（存在オラクル、テナント越えの書き込み、リダイレクトを追従しないこと、本文プレビューなし）には失敗する必要があります。プローブを編集したら実行してください。 |
| `leak_scan.sh` | 公開前の漏えいスキャン（秘密鍵ブロック、トークン形式の文字列、公開IPv4アドレス、メールアドレス、独自の非公開語 `--terms ファイル`＝リポジトリ外に置く）。件数とファイル名のみ表示します。`.git` は対象外です。何か見つかれば終了コード1です。 |

`tenant_probe.py` の制限（これらはcurlや自前のコードで行ってください）: マルチパートのアップロード、Webhookのような生ボディ/HMAC署名付きボディ、並列リクエスト、応答からのIDの取得。
計画ファイルはコードです（`snapshot_cmd` はシェルで実行されます）。トークンは `ENV:NAME` でのみ参照でき、共有の場所には置かないでください。並行処理のテストは `references/08` を参照してください。

どちらのツールも「必ず失敗する」合成データ（わざと脆弱にしたモックサーバー、漏えいを仕込んだディレクトリ）で動作を確認済みです。失敗できない検査はテストではありません（FL-08）。

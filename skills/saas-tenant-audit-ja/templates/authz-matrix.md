# エントリポイントのインベントリと 2 テナントのマトリクス

## インベントリ（メソッド + パスごとに 1 行）

| # | メソッド | パス | 認証 | テナントの導出元 | 受け付ける ID（パス / クエリ / ボディ / 保存済み JSON） | 状態ルール | 副作用 | コスト | リミッター / クォータ | 拒否の規約 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | GET | /api/v1/things/{id} | ユーザー | トークン | パス | 有効のみ | なし | なし | – | 404 |

## マトリクス（`実測値` は実行結果から埋める。記憶から埋めない）

フィクスチャ: テナント A（攻撃者）id=…、テナント B（被害者）id=…、対照 ID（存在したことがない）=…
B のデータのベースライン取得済み: はい/いいえ（方法: …）

| # | 実行者 | 対象 | リクエスト | 期待値 | 実測値 | ボディ形状 | B は変化したか | 結果 |
|---|---|---|---|---|---|---|---|---|
| 1 | A | A（自分） | GET /things/{A1} | 200 | | | n/a | 対照 |
| 2 | A | B | GET /things/{B1} | 404 | | | n/a | |
| 3 | A | 存在しない | GET /things/{X} | 404 (== #2) | | | n/a | |
| 4 | 匿名 | B | GET /things/{B1} | 401 | | | n/a | |
| 5 | A | B | PATCH /things/{B1} | 404 | | | はい/いいえ | |
| 6 | A | A + ボディ内に B の ID | PATCH /things/{A1} {"parent_id": B1} | 404 または 422（合意済み） | | | はい/いいえ | |

> 列は例です。対象リソースの実際の状態（例: draft/sent/paid/void/deleted）を使い、製品が業務ルールのエラーで正当に応答する箇所には `409`/`422` を記録します。`expected` には許容するコードを複数書けます（例: `404 or 422`、オーナーと合意したもの）。
